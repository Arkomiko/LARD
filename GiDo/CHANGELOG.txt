История изменений MiliPlain
===========================

Формат записи: версия, дата, затем разделы «Добавлено», «Исправлено»,
«Сломано» (только те, где есть что написать). Новые версии — сверху.


0.0.10a — 2026-10-25
--------------------

Добавлено:
- Начало MiliPlain — переписывание программы с нуля (раньше она называлась LARD).
  LARD остаётся названием метода ввода нот: левая кнопка ставит, правая удаляет.
- Новая структура папок: app/ (ui, engine, shell), bridge/, tools/, presets/,
  mods/, scripts/, GiDo/. Описание каждой папки — в GiDo/map/.
- Журнал решений GiDo/DECISIONS.md, этот журнал изменений, README.md,
  временный LICENSE, кнопка донатов (.github/FUNDING.yml).
- Черновики документов: ARCHITECTURE.md (устройство программы со схемой),
  BUILD.md (что установить для сборки), DAW_SUPPORT.md (таблица поддержки DAW).
- Выбран стек: C# (.NET 10, WebView2) для окна и движка, TypeScript для
  интерфейса, C++ для моста MiliPlain Bridge. Проверен прототипами;
  окончательное подтверждение — после ручной проверки в DAW.

Добавлено на этапе 1 (ядро проекта):
- Программа MiliPlain.exe: окно на WebView2, интерфейс на TypeScript,
  движок на C#. Собирается одной командой: scripts/build.ps1.
- Модель проекта: каналы, паттерны с нотами нескольких каналов, нота
  (канал, высота, начало, длительность, velocity, mute, цвет 1–16), темп, размер.
- История отмены: все правки проекта, 100 шагов по умолчанию (меняется
  в настройках); перетаскивание будущего пианоролла — одним шагом.
- Файл проекта .mpj (ZIP-архив с project.json): «Новый», «Открыть»,
  «Сохранить», «Сохранить как». Запись надёжная — при сбое старый файл цел.
  Испорченный файл не открывается, а показывает, что именно в нём не так.
- Миграции формата: файлы старых версий будут открываться новыми.
- Автосохранение раз в 5 минут (меняется в настройках, 0 — выключено),
  5 последних резервных копий на проект, окно «Резервные копии».
- Вопрос «Сохранить изменения?» при закрытии окна и открытии другого проекта.
- Настройки программы и журнал работы в %APPDATA%\MiliPlain.
- Простой рабочий интерфейс для проверки: проект, каналы, паттерны, ноты
  таблицей. Горячие клавиши Ctrl+N, O, S, Shift+S, Z, Y.
- Тесты: 68 для интерфейса, 30 для движка (scripts/test.ps1).

Добавлено на этапе 2 (пианоролл LARD):
- Пианоролл на месте таблицы нот: сетка с долями и тактами, клавиатура
  с подписями октав, линейка тактов, ноты 16 цветов с названиями.
- Метод LARD: левая кнопка ставит ноту и сразу тянет её, правая удаляет,
  зажатая правая стирает протяжкой.
- Инструменты Draw (P), Paint (B), Delete (D), Select (E) — клавиши как
  в FL Studio, работают и в русской раскладке.
- Перемещение и растягивание нот и выделенных групп, выделение рамкой
  (в Select или Ctrl + протяжка), Shift/Ctrl — добавить к выделению.
- Привязка к сетке (такт, доля, 1/2, 1/3, 1/4, 1/6, 1/8 доли, без привязки),
  Alt — временно без привязки. Квантизация (Ctrl+Q).
- Команды: Delete, Ctrl+A, Esc, Ctrl+C / X / V, Ctrl+B (дублировать),
  стрелки вверх/вниз (полутон), Ctrl + стрелки (октава), влево/вправо (шаг).
- Прокрутка колесом, Shift — вбок, Ctrl — масштаб, Alt — высота строк,
  средняя кнопка — тянуть вид; кнопка «Показать все ноты».
- Горячие клавиши устроены тремя слоями (команда → таблица → диспетчер):
  на этапе 7 их можно будет переназначать.
- Временная кнопка «Тест: 5000 нот» для проверки скорости.
- Тесты: 127 для интерфейса, 30 для движка.

Исправлено на этапе 2:
- Окно не растягивало содержимое на всю высоту.

Сломано:
- Весь код старой версии LARD (форк signal) удалён из репозитория.
  Он остаётся в истории git.
- Таблицы нот больше нет: ноты правятся в пианоролле.
