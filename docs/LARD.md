# LARD — Left Add / Right Delete

Форк [signal](https://github.com/ryohey/signal) (MIT) — секвенсор на TypeScript + React + WebGL.
Цель: паттерн-ориентированный MIDI-редактор в логике FL Studio, работающий **рядом** с Ableton Live,
с перетаскиванием паттернов прямо в аранжировку.

## Почему форк signal, а не LMMS

| Критерий | signal (TS/React) | LMMS (C++/Qt) |
|---|---|---|
| Сборка на Windows | `npm install` → 22 сек | MSVC + Qt + CMake, часы возни |
| Порог входа | правка одного `.tsx`, hot-reload | пересборка всего проекта |
| Drag-and-Drop в Ableton | `webContents.startDrag` (Electron) | нативный OLE вручную |
| Пианоролл «ЛКМ создать / ПКМ удалить» | **уже реализован** | нужно писать |

## Дорожная карта

Форк склонирован, зависимости встали, сборка зелёная (4/4 задачи), dev-сервер отвечает.

### M1 — Панель паттернов и стойка инструментов ✅
Раскладка как в FL Studio: список паттернов слева, стойка инструментов справа,
пианоролл между ними. Переключатели панелей — по краям тулбара.

Реализовано в `source_dev/app/src/lard/pattern/`:

| Файл | Роль |
|---|---|
| `Pattern.ts` | сущность паттерна и чистые функции над ней |
| `usePatternList.ts` | стор на jotai и логика обмена нотами |
| `PatternList.tsx` | панель со списком и кнопкой создания |
| `PatternListItem.tsx` | строка списка: выбор, переименование, дублирование, удаление |
| `Pattern.test.ts` | тесты чистых функций (8 штук) |

Стойка инструментов — это существующий `TrackList` апстрима, перенесённый направо
через `primary="second"` у сплиттера и открытый по умолчанию.

#### Модель обмена нотами

Пианоролл не знает о паттернах вообще — и это сделано намеренно.
В треках песни в любой момент лежат ноты **только активного паттерна**,
остальные ждут своей очереди в сторе. При переключении ноты трека выгружаются
в покидаемый паттерн, а на их место загружаются ноты выбранного.

Почему так: альтернатива — переписать модель данных `Song`/`Track`, а вместе с ней
пианоролл, выделение, историю и экспорт. Обмен нотами даёт рабочие паттерны,
не трогая ни строки в редакторе.

Две детали, без которых модель не работает:

- **Идентификаторы событий в паттерне не хранятся** (`PatternNote = Omit<NoteEvent, "id">`).
  Их выдаёт сам трек при вставке; сохранённые id разошлись бы с реальными
  после первой же загрузки.
- **Обмен идёт в одной MobX-транзакции.** Иначе на каждый трек приходится два
  действия, и пианоролл успевает отрисовать состояние, где ноты уже удалены,
  а новые ещё не вставлены — это видно как мигание.

Служебные события (смена инструмента, контроллеры, темп) при обмене не трогаются:
они принадлежат треку, а не паттерну.

#### Ограничения текущей модели

Честно, чтобы не наткнуться позже:

1. **Паттерны не сохраняются в проект.** Стор живёт в памяти; после перезагрузки
   останутся только ноты активного паттерна — они лежат в треках и попадают в MIDI.
2. **История не знает о паттернах.** `Ctrl+Z` после переключения может вернуть
   ноты предыдущего паттерна, оставив в списке выбранным текущий.
3. **Нет аранжировки паттернов.** Слышен и редактируется всегда один — как в
   пианоролле FL, но плейлиста, раскладывающего паттерны по времени, пока нет.

Все три снимаются одним шагом: перенести список паттернов из jotai в модель `Song`.
Тогда история и сохранение накроют их автоматически. Делать это стоит вместе
с собственным форматом проекта, потому что MIDI паттерны хранить не умеет.

### M2 — Drag-and-Drop в Ableton ✅

Паттерн перетаскивается из списка прямо в аранжировку Ableton и становится MIDI-клипом.

Цепочка: `dragstart` на строке списка → сборка MIDI из нот паттерна
(`patternToMidi.ts`) → IPC `startPatternDrag` → запись `.mid` во временную папку →
`webContents.startDrag({ file, icon })`.

| Файл | Роль |
|---|---|
| `source_dev/app/src/lard/pattern/patternToMidi.ts` | сборка MIDI-файла из нот паттерна |
| `source_dev/app/src/lard/pattern/useDragPatternToDaw.ts` | начало переноса из окна |
| `source_dev/electron/src/ipcMain.ts` → `startPatternDrag` | запись файла и вызов `startDrag` |
| `source_dev/app/src/lard/pattern/patternToMidi.test.ts` | тесты, включая обратный разбор файла |

#### Что важно знать

- **Работает только в окне программы.** В браузере такое невозможно принципиально:
  вкладке запрещено отдавать файлы другому приложению. Поэтому строка списка
  становится перетаскиваемой только при `isRunningInElectron()`.
- **Атрибута `draggable` мало.** В `components/Theme/GlobalCSS.tsx` всем `div`
  задано `-webkit-user-drag: none`, и с ним движок не рождает `dragstart` вовсе:
  атрибут висит, а перенос не начинается. Строка списка переопределяет это
  правило через `-webkit-user-drag: element` — селектор по классу специфичнее
  селектора по тегу. Симптом, если забыть: нажатие на паттерн просто выделяет
  его, и ничего не происходит.
- **Штатный перенос HTML5 отменяется** (`e.preventDefault()` в `dragstart`).
  Он умеет ходить только внутри страницы; дальше перенос ведёт главный процесс.
- **Дирижёрский трек копируется целиком.** Без темпа и размера Ableton подставит
  свои, и ноты разъедутся по времени.
- **Ноты берутся из паттерна, не из треков.** Исключение — активный паттерн:
  его ноты лежат в треках песни, поэтому снимаются оттуда. Без этой развилки
  перетаскивание активного паттерна давало бы пустой файл.
- **Иконка переноса обязательна.** При пустой `startDrag` бросает исключение,
  поэтому берётся `source_dev/electron/icons/icon.png`, уменьшенная до 64×64.
- **Отдаётся ровно занятый отрезок буфера.** У `Uint8Array` он может быть частью
  более крупного `ArrayBuffer`, и тогда в файл попал бы мусор.

#### Ограничения

- Файл кладётся во временную папку системы и не удаляется. Имя берётся из имени
  паттерна, так что повторный перенос перезаписывает прежний файл.
- Ableton создаёт клип из **копии** файла. Изменения паттерна в LARD в уже
  перенесённый клип не попадают — это односторонний экспорт, не связь.

### M3 — Инструменты пианоролла как в FL Studio ⚠️ частично

Сделано: четыре инструмента и буквы FL для них.

| Инструмент | Клавиша | Поведение |
| --- | --- | --- |
| Рисование (Draw) | `P`, `1` | ЛКМ ставит ноту и тащит её, ПКМ удаляет |

Это безопасно: обработчик редактора вложен в глобальный и останавливает
всплытие, поэтому вне пианоролла перемотка работает по-прежнему.

- **Mute (`T`)** — упирается в модель данных: у `NoteEvent` в

- **Slice (`C`)**, **Zoom (`Z`)**, штамп аккордов, Riff Machine.
- **Настраиваемая раскладка.** Клавиши по-прежнему зашиты в массивы `actions`
  внутри хуков. Чтобы раскладку можно было менять в настройках, нужно
  разделить на три слоя: команда (`tool.pencil`) → таблица «команда →
  сочетание» → диспетчер, читающий активную таблицу.

## Запуск

Все команды выполняются из папки `source_dev` — там лежит `package.json`.
Подробная инструкция для разных сред: [`docs/install.md`](../docs/install.md).

### Окном (единственный способ)

```sh
cd source_dev
npm install                     # один раз
npm install --prefix core/electron   # один раз
npm run dev:lard                # сервер и окно программы
```

Одна команда поднимает две вещи: фоновый сервер, который раздаёт окну
исходники, и само окно. Правки видны сразу, без перезапуска.

Браузер не открывается намеренно: перетаскивание файлов в Ableton из вкладки
невозможно в принципе, а без него LARD теряет смысл.

### Редакторы пресетов

```sh
npm run dev:theme    # редактор тем, своё окно
npm run dev          # программа и все редакторы сразу
```

## Подводные камни Electron на Windows

Три проблемы, каждая из которых полностью блокирует запуск:

1. **`ELECTRON_RUN_AS_NODE=1` в терминале VS Code.**
   Electron стартует как обычный Node: окна нет, а `require("electron")` возвращает
   строку с путём к бинарнику вместо модуля — падает первое же `app.getVersion()`.
   Решение — `source_dev/core/electron/scripts/launch.js`, который снимает переменную и уже затем
   запускает Electron. На него переведены запуск окна и `nodemon`, а у окон
   редакторов — свой такой же `core/tools_shell/launch.cjs`.

2. **`electron-log` нельзя бандлить.**
   Его точка входа выбирает вариант (`main` / `renderer` / `node`) по `process.type`
   в рантайме; rollup эту развилку схлопывает и подставляет `node`-вариант,
   который падает на `log.initialize()`. В `rollup.config.js` пакет вынесен в `external`,
   а импорты в главном процессе переведены на явный подпуть `electron-log/main`.

3. **npm не может скачать бинарник Electron.**
   Его тянет отдельный HTTP-клиент, на который не действует `--fetch-retries`,
   и он рвёт TLS-соединение с GitHub. При провале npm откатывает установку целиком.
   Обход — поставить пакеты без бинарника и скачать его отдельно:

   ```sh
   ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm install --prefix core/electron
   curl -L --retry 10 --retry-all-errors -C - -o electron.zip      https://github.com/electron/electron/releases/download/v31.6.0/electron-v31.6.0-win32-x64.zip
   ```

   Затем распаковать в `source_dev/electron/node_modules/electron/dist/` и создать рядом файл
   `path.txt` с единственной строкой `electron.exe` **без перевода строки в конце**.
   Контрольная сумма для проверки лежит в `source_dev/electron/node_modules/electron/checksums.json`.

## Отличия от upstream

Изменения форка помечены в коде комментарием `// LARD:`.

### Исправленные баги

- **Выделение области по Ctrl не работало на Windows.**
  `source_dev/app/src/components/PianoRoll/MouseHandler/usePencilGesture.ts` проверял только `e.metaKey`
  (это Cmd на macOS и клавиша Win на Windows). Добавлен `e.ctrlKey`.
  Для сравнения — в соседнем `useMoveSelectionGesture.ts` апстрим написал условие правильно.
- **Ползунок воспроизведения не тянулся мышью.**
  `source_dev/app/src/components/PianoRoll/CanvasPianoRuler.tsx` ставил позицию только по `onMouseDown`,
  без отслеживания протяжки. Добавлен скраб через `observeDrag`; прямоугольник канваса
  запоминается на момент нажатия, потому что при выходе курсора за его границы
  `offsetX` события становится непригодным.
- **Vite биндился только на IPv6.** В `source_dev/app/vite.config.mts` добавлен `host: "127.0.0.1"` —
  без него Chrome отдаёт `ERR_CONNECTION_REFUSED` на `localhost:3000`.

### Убрано из интерфейса

LARD — дополнительный инструмент к Ableton, а не самостоятельная DAW.
Вкладки «Аранжировка» и «Темп» скрыты флагом `showDawTabs` в
[`source_dev/app/src/lard/features.ts`](../source_dev/app/src/lard/features.ts) — вместе с горячими клавишами
`Ctrl+2` / `Ctrl+3`, иначе можно уйти в раздел, из которого нет возврата.
Код редакторов оставлен на месте: поведение возвращается одним флагом,
и слияние с upstream не ломается.

## Темы

Темы живут в папке [`Tools_presets/Theme/`](../source_dev/Tools_presets/Theme/) — обычными
JSON-файлами. **Один файл — одна тема**, имя файла и есть имя темы.
Подробное описание всех полей: [`Tools_presets/Theme/README.md`](../source_dev/Tools_presets/Theme/README.md).

Устройство такое же, как у языков, и по той же причине: положил файл — тема
появилась в настройках, регистрировать в коде ничего не нужно.
`source_dev/app/src/theme/Theme.ts` собирает папку через `import.meta.glob`.

Поле `label` внутри файла задаёт подпись в списке. Остальные поля —
цвета; всё, что не указано, наследуется из базовой тёмной темы, поэтому
тема из трёх строк работает, а опечатка в ключе не оставляет интерфейс
без цвета. Функция `getTheme` подставляет тёмную тему, если выбранной
больше нет — иначе удалённый файл ронял бы интерфейс.

Встроены четыре темы: `dark`, `light`, `windows10` (системный синий
`#0078d4`, шрифт Segoe UI) и `flstudio`.

Палитра `flstudio` не подобрана на глаз: цвета сняты пипеткой со скриншотов
официального руководства FL Studio 2026 (`pianoroll_general.png`) —
фон дорожек `#42545f`/`#3b4d58`, линия такта `#1a2c37`, линия доли `#2e404b`,
нота `#a4e3b0`, ghost-нота `#647681`.

Заодно `cursorColor` вынесен в тему: раньше курсор воспроизведения был
жёстко красным (`vec4(1,0,0,1)`) мимо всякой темы.

## Локализация

Языки живут в папке [`Tools_presets/Language/`](../source_dev/Tools_presets/Language/).
**Один файл — один язык**, имя файла и есть код языка (`ru.ts` → `ru`).

Папка вынесена из `source_dev/app/src` намеренно: переводы правятся как обычные тексты,
без хождения по дереву исходников. Тем же принципом вынесены и темы.

Чтобы добавить язык, достаточно положить туда файл. Регистрировать его нигде
не нужно: `localization.ts` собирает папку через `import.meta.glob`, а список
в настройках строится из тех же найденных файлов.

### Формат файла

```ts
import type en from "./en"

/** Подпись в списке языков. */
export const label = "Русский"

const translation: Partial<typeof en> = {
  "piano-roll": "Пианоролл",
}

export default translation
```

`Partial<typeof en>` даёт две вещи сразу: перевод может быть неполным,
а опечатка в имени ключа не пройдёт проверку типов.

### Английский — основа

`en.ts` отличается от остальных: он задаёт **полный набор ключей** и служит
запасным вариантом. При сборке таблицы каждый язык получается как
`{ ...en, ...перевод }`, поэтому непереведённая строка остаётся английской,
а не пропадает. Программа работает и тогда, когда в папке нет ничего,
кроме `en.ts` — переводы необязательны.

Удалять `en.ts` нельзя: на нём держится и типизация ключей (`LocalizationKey`),
и подстановка.

### Подбор языка по локали браузера

Правила строятся из имён файлов: положили `ru.ts` — локаль `ru-RU` подхватится
сама. Длинные коды проверяются первыми, иначе `zh` перехватил бы `zh-Hans`.
Региональные варианты китайского (`zh-TW` → `zh-Hant`) из имени файла
не выводятся и заданы отдельным списком в `useLocalization.ts`.

### Правка в tsconfig

Для `import.meta.glob` понадобилось два изменения в `source_dev/app/tsconfig.json`:
`"module"` с `es2015` на `esnext` (при `es2015` компилятор запрещает
`import.meta`) и тип `vite/client` в списке `types`. На выпуск это не влияет —
сборку делает Vite, а `tsc` здесь только проверяет типы.

## Соглашения форка

- Весь код, специфичный для LARD, живёт в `source_dev/app/src/lard/`.
- Точечные правки в файлах апстрима помечаются комментарием `// LARD:` с объяснением причины.
- Комментарии — на русском.
- Чистая логика выносится из компонентов в отдельные файлы и покрывается тестами
  (`vitest`), UI-обвязка — нет.

## Синхронизация с upstream

```sh
git fetch upstream
git merge upstream/main
```
Работа ведётся в ветке `lard`, `upstream` — оригинальный репозиторий signal.
